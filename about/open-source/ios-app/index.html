About/ios_app

03 / Open Source / ios_app

iOS is a SwiftUI client wrapped around the same engine.

Swift owns lifecycle, touch, identity, and platform presentation. Rust still owns the world.

The ios_app repository is intentionally an adapter rather than a second game implementation. SwiftUI drives loading and screen state, GameViewModel owns the engine lifecycle and 60 Hz tick, and the app sends the same package data and world-socket messages as the browser.

The app can start with a bundled manifest and script, use a cached manifest on the next launch, and refresh declarative content from the web host for a later launch. Executable rules remain bundled; this gives content some update room without downloading arbitrary native behavior.

App state
ContentView.swift → GameViewModel with published loading, frame, world, socket, identity, and moderation state
Package loader
GamePackage.swift decodes the manifest, validates the start world, and manages bundled/cached content
Engine bridge
EngineBridge.swift copies UTF-8 buffers into the C ABI and decodes the float snapshot into Swift value types
Metal surface
RustGameSurface.swift hosts an MTKView; its delegate syncs and draws the Rust renderer

Frame and lifecycle

Swift owns the clock.

A Combine timer ticks the view model at 60 Hz when the game is presented. The view model guards the first tick, clamps the delta, pauses movement while the username editor is open, passes remote players into Rust, steps the engine, follows the active world index, sends movement, and publishes the next frame for SwiftUI.

The MTKViewDelegate owns the platform render cadence. It creates the renderer from the view's CAMetalLayer, resizes it when drawable dimensions change, syncs the engine, draws, and tears it down with the view.

Networking and configuration

Native identity, shared protocol.

  • WorldSocketClient uses URLSessionWebSocketTask, sends movement only when meaningfully changed and no faster than 12 Hz, and reconnects with bounded backoff.
  • Player IDs and usernames persist in UserDefaults; settings-room visibility is sent separately from movement.
  • Debug builds default to localhost; Release builds default to the deployed package and Worker, with environment overrides for LAN testing.
  • The Xcode build phase compiles the sibling Rust crate for the selected simulator or device target and links the static library.

The native integration is intentionally boring at the boundary: copy bytes in, call the engine, decode a known snapshot, and let SwiftUI handle platform UX. That makes iOS-specific work safer to review.
